# KORLIX AI Visibility — first release

## Start
Open **AI Visibility** from the home quick actions or tools. In **Business**, save the four required fields: business name, public HTTPS website, service/product category, and target market. Add optional verified facts and optionally customize the three discovery questions. Questions must describe customer needs without including your brand or website. Save opens **Overview**; approve AI sharing and select **Run visibility scan**. Reopen this screen to follow an existing scan.

## What a scan measures
Each scan runs three independent, unbranded OpenAI API web-search answer samples using the existing Astra extra-high reasoning configuration. The provider request for each sample excludes the target brand and website. KORLIX calculates literal whole-name matches and website citations locally from the answers and actual citation annotations. The report shows full sampled answers, citations, and separately labeled retrieved links. Common business names can produce ambiguous matches. These are three observations, not rankings, share of voice, or a prediction of recommendations. Consumer ChatGPT, Google AI Overviews, Gemini and Perplexity are not measured.

A separate website search, restricted to the supplied website domain, prepares up to eight observations, six prioritized actions, and three editable content drafts: a service page, product description, and FAQ. Observation source links must appear in actual provider retrieval sources. Unsupported links are removed. If website material cannot be retrieved, the report says so and offers only draft scaffolds based on owner-supplied details and general guidance. This is not a technical crawl, robots/indexing/structured-data audit, or proof that the entire website lacks information. Drafts require fact checking and replacing missing-detail placeholders before publication. No content is published automatically.

## Progress and comparison
Reports retain their original business snapshot, questions, model/method and observation date. Comparisons require the same normalized brand, website domain, questions, model and method and an earlier completed scan. Edited questions or a different business cannot create misleading deltas. Check off suggested actions and optionally record inquiries, bookings and notes manually; these records do not prove AI attribution or causation and cannot change measured results. Copy reports, answers and draft content; open their source links for verification. Monitoring is manual in this release, with no recurring schedule or automatic notifications.

## Access, credits and privacy
Business setup and report management require sign-in. Scans use the existing Ultra Premium/Enterprise entitlement and cost three existing credits per completed report. Failed or interrupted scans charge nothing. Replaying a request does not dispatch or charge twice. No new paid plan or payment product is created.

AI consent covers sending questions, business setup and website material to OpenAI. Requests use store:false. Records remain private to the backend-verified account; there is no client-selectable owner. Both tables have RLS enabled with direct anonymous/authenticated access revoked, and the security-invoker RPC is executable only by the service role. Account/session changes discard stale client responses and clear private editor state. Logs exclude business inputs and report contents. Removing a report or clearing AI Visibility requires confirmation; clearing removes the profile and all retained reports. Account deletion cascades records. Deletion does not refund completed work or erase third-party provider retention.

## Limits and recovery
One active scan per account, two starting/running scans per backend process, six starts per hour including failed attempts, and the latest 60 retained reports. Each scan has three bounded sample calls followed by one website review; provider calls have finite deadlines and no automatic retries. Jobs persist their state in the database but execute in the existing backend process, not a durable external queue. A restart can interrupt work; runs older than 12 minutes become failed without charge when the account next accesses the feature. A completed report and the three-credit debit commit atomically. Saved progress never changes report observations.

## API and rollout
API prefix `/api/ai-visibility`: GET snapshot; PUT `/profile`; POST `/runs` with UUID request_key and consent:true; GET/PATCH/DELETE `/runs/:id`; DELETE base with confirmed:true. All responses use Cache-Control:no-store. Apply the additive ai_visibility migration to the existing project, align the repository filename to the actual migration-history version, deploy the backend, then deploy the frontend. Health reports aiVisibility version, model, effort, method, sample count and credit cost. No new secrets, services, storage buckets or scheduled jobs are needed. Roll back the service commits if necessary while preserving additive tables and user records.

## Brand rule
**NOVA refers only to AI voice. KORLIX names the AI agent doing business, chat, email, analysis, styling and other non-voice work.** Current user-facing surfaces and active feature documentation follow this rule. Legacy URLs, internal bindings, identifiers and historical records remain compatible; voice wake words and voice behavior are preserved.

## Verification
Backend tests execute the real SQL migration in PGlite and exercise ownership, revoked grants, idempotency, atomic charging, consent/access, timeouts, progress validation, deletion, unbranded prompts, source validation and computed metrics. Flutter tests cover confirmed profile saving, visible mobile validation/server errors, session changes, consent, retry identity, resumed polling, source/draft actions, comparable scans, manual progress and confirmed deletion at desktop/phone widths with larger text. Provider responses in automated tests are fixtures. Public deployment checks do not prove provider output quality: the first signed-in real scan remains an acceptance check.

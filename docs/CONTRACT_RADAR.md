# KORLIX Contract Radar

## Start
Open **Contract Radar** from the home quick actions or tools. The **Find** page asks for business name, services and service area. Choose **Save & find contracts** to save those details and start discovery in one action; **Save profile changes** saves without starting AI search. Capacity, credentials and NAICS codes are under **More business details (optional)**. Returning users can enter an optional search focus, edit their business or service area inline, and choose **Find contracts**.

Results from the latest completed search can be filtered by keyword and notice type, sorted by deadline, or have past deadlines hidden. These controls work locally and use no credits. Unknown dates remain visible; early leads include sources-sought and presolicitation notices, which may not be requests for bids yet. Filtering and sorting preserve each result's original job/index when saving. Clear filters restores the full result set and original search order. A newly completed search resets the result filters.

Choose **View official notice**, then **Save contract** for useful leads. Open **Saved** to track progress and prepare a bid. **Paste an RFP** accepts corporate or other notices. In a saved opportunity, add the complete RFP text, choose **Review with KORLIX**, review the evidence and missing information, and copy the working draft.

## Coverage and accuracy
Profile setup requires only business name, services/products and service area, marked with *. Optional fields can remain empty. Save highlights and focuses a missing required field; network failures keep the entries and show feedback beside Save and in a visible notification. Successful saving uses the returned server profile immediately, displays confirmation and opens Find without requiring a second network read. A pending save disables duplicate submissions. Failed profile saving never starts discovery; AI consent is still required before discovery. A confirmed profile edit clears the previous search request key, while retrying unchanged search inputs reuses the key.

Choose official sources for the United States (SAM.gov, NYC City Record and New York State OGS), Canada (CanadaBuys), United Kingdom (Find a Tender and Contracts Finder), or Jamaica (GOJEP and Ministry of Health). Official web discovery uses OpenAI Responses web search restricted to the selected public procurement domains. Coverage remains selective, and some portals are not fully searchable. The separate Direct SAM.gov source uses the official U.S. federal API when the server has a SAM.gov API key; it uses zero AI credits. Missing connection is shown as setup information with official web search still available. Accepted results must have an individual official notice URL present in the actual provider retrieval sources. Unsupported URLs, duplicates, awards and known past response dates are rejected. Notice classifications distinguish solicitations, sources-sought and presolicitations. Dates, summaries and relevance are search-derived: check the original notice, attachments, amendments, response time and eligibility before acting.

Other RFPs can be pasted (18,000 characters maximum) or uploaded as PDFs up to 5 MiB / 60 pages. Extraction is server-side and uses no AI credits; the PDF file is not retained. Review the extracted text, warnings and truncation notice, then explicitly use or replace the editor text before saving. Scanned PDFs without selectable text need OCR outside this workflow. Uploading does not start an AI review. Arbitrary source URLs are not fetched. Summary-only reviews are visibly marked. Requirement evidence must match an exact passage of supplied material; unsupported evidence is removed and the requirement is marked for verification. Profile qualifications are self-reported. KORLIX prepares drafts with missing-input placeholders; it does not verify credentials, set prices, promise awards, submit bids, contact buyers or move pipeline stages automatically. Submitted/won stages are manual records.

## Access and credits
Profiles, saved opportunities and manual pipeline management are available to signed-in users. AI discovery/review uses the existing Ultra Premium/Enterprise entitlement and consent gate, Astra at extra-high reasoning, and one existing credit per successful request. Searches with no accepted opportunities use zero credits. Failed/interrupted requests do not charge; replaying the same request does not charge or dispatch twice. This release does not create a new payment product.

## Privacy and lifecycle
All records are scoped to the backend-verified account. Private RLS-enabled Radar tables have no direct anonymous/authenticated access; only the service role can execute the security-invoker RPC. Client requests never select an owner. Session changes discard stale responses and clear private editor state.

Discovery sends services, service area, optional NAICS and the search focus to OpenAI/web search. Reviews send the saved profile and selected notice text or summary to OpenAI after AI consent. Requests set store:false. Profile/notice snapshots and results remain in the private Radar records. Search retrieval uses official public sources. Request bodies, RFP text and profile details are not logged by the module.

Removing a saved opportunity removes its review jobs, but its earlier discovery result can remain in search history. **Clear my radar** removes that account's profile, opportunities, job history, monitoring settings, saved searches and alerts. It does not reverse already consumed credits or request deletion from third-party provider retention. Account deletion cascades Radar records. Editing RFP text invalidates its saved review; profile updates do not rewrite historical reviews, whose profile snapshot time is displayed.

## Runtime limits and recovery
Jobs run in the existing backend process, with database-backed state. Navigating away and reopening resumes polling. A server restart can interrupt work; jobs older than eight minutes become failed without charge and can be restarted manually. AI discovery and review do not automatically retry. The separate daily monitoring worker stores settings, leases and results in the database and runs in the existing backend process. One active job per account, three starting/running jobs per process, 12 starts per account per hour, 100 saved opportunities, at most 100 retained job records and 12 jobs returned in the current view. Provider calls have finite deadlines and no automatic retries. Inputs and stored JSON sizes are bounded.

## API and deployment
API prefix: /api/contract-radar. GET reads the private snapshot; DELETE requires confirmed:true. PUT /profile saves the profile. POST /opportunities accepts an owned completed discovery job/index or a manual RFP; PATCH/DELETE /opportunities/:id updates/removes it. POST /jobs takes a UUID request_key, kind, consent and optional query/opportunity_id. GET /jobs/:id polls. Responses use Cache-Control:no-store.

Apply the additive contract_radar migration before deploying the backend, then deploy the frontend. Align the repository migration filename with the version returned by Supabase migration history. Existing OpenAI and database configuration is reused. The optional direct SAM.gov feed needs server-side SAM_GOV_API_KEY (SAM_API_KEY is also accepted). No raw PDF storage bucket or new service plan is needed. Apply the additional radar_monitor migration before enabling the monitor backend; the worker starts with all accounts off. Roll back both services to their previous release commits if needed; leave additive tables intact to preserve user records. Never drop customer data as a rollback step.

## Daily monitoring and alerts
Choose **Save this search** on Find to keep the current keywords, first NAICS code and optional U.S. state code as a SAM.gov search. Direct and saved search keywords are limited to 160 characters; the full business profile retains all entered NAICS codes. Saving a search does not turn on global monitoring. Keep up to five searches; repeated identical saves reuse their request identity while the screen is open, and the server deduplicates matching filters after reopening.

Open **Saved searches & alerts** to choose a daily local time, IANA timezone and deadline reminder offsets. Enabling automatic checks requires an explicit confirmation that explains the zero AI-credit cost and in-app delivery. No buyer messages or bids are sent. With no SAM.gov key, saved deadline reminders still work. Direct matches and SAM notice-detail checks need the feed connection. Each search shows its last check, errors and latest results, with official links and one-action saving to the pipeline.

Daily digest alerts summarize the searches; deadline alerts link to saved opportunities; notice-change alerts show changed deadlines, titles or active status when supplied by SAM. They do not prove every attachment or amendment has been captured. Check the official notice and closing time. Mark alerts read individually or together; clearing visible history requires confirmation and preserves monitoring settings. Up to 100 recent alerts are shown and alerts older than 180 days are pruned. Checks are bounded to ten saved SAM notices per daily pass, so a large pipeline may take several daily passes to revisit every notice. Failed feed checks are surfaced and retried at the next scheduled pass. Pause monitoring at any time.
